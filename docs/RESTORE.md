# Відновлення бази

Що робити, якщо Supabase-проєкт видалено, зламано або дані зіпсовано.

## Що є

- **Міграції** (`supabase/migrations/`) — уся схема: таблиці, функції,
  політики доступу. Перша з них, `20260901_base_schema.sql`, відтворює те, що
  колись жило лише в панелі Supabase. Накочування всіх міграцій по черзі на
  порожній проєкт дає робочу базу без даних.
- **Щотижнева копія даних** — робота «Резервна копія бази»
  (`.github/workflows/backup.yml`), неділя 02:17 UTC. Архів зашифровано
  паролем `BACKUP_PASSPHRASE`, зберігається 35 днів (п'ять тижнів) в
  Actions → робота → Artifacts.

## Відновлення даних у новий проєкт

1. Створити новий проєкт Supabase. Увімкнути анонімний вхід
   (Authentication → Providers → Anonymous) і налаштувати пошту — як у
   README, розділ «Налаштування пошти».
2. Завантажити останній архів з Actions і розшифрувати:

   ```sh
   gpg --decrypt inclusive-games-2026-10-18.tar.gz.gpg > backup.tar.gz
   tar -xzf backup.tar.gz
   ```

3. Відновити дані (рядок підключення — з нового проєкту):

   ```sh
   pg_restore --no-owner --no-privileges --clean --if-exists \
     --dbname "$NEW_DB_URL" backup/inclusive-games-2026-10-18.dump
   ```

   `--clean` прибирає те, що вже є, перед відновленням. На порожньому проєкті
   помилки «does not exist» на цьому кроці — нормально.

4. Докотити міграції, новіші за копію (їх файли датовані): у SQL-редакторі
   або `supabase db push`.
5. Змінити `VITE_SUPABASE_URL` і `VITE_SUPABASE_ANON_KEY` на Vercel і
   `connect-src` у `vercel.json` (CSP пускає лише один проєкт Supabase).
6. Перевірити: вхід учителя поштою, вхід дитини за кодом групи, результати в
   групі, адмін-панель.

## Відновлення лише схеми (без даних)

Порожній проєкт → усі файли `supabase/migrations/*.sql` по черзі, за іменем.
Так перевірено на чистому Postgres 16 із заглушкою auth-схеми Supabase.

## Перевіряти, а не сподіватися

Копія, яку ніхто не відновлював, — не копія. Раз на семестр: розгорнути
останній архів у тимчасовий проєкт (кроки 1–3) і переконатися, що групи й
результати на місці. Тимчасовий проєкт потім видалити — в ньому справжні дані
дітей.
